# Day 13: SQL Set Operators and Joins

## 1. UNION

### What is UNION?

`UNION` combines the results of two or more `SELECT` queries into a single result. It removes duplicate rows automatically.

### Syntax

```sql
SELECT column_name FROM table1
UNION
SELECT column_name FROM table2;
```

### Example

```sql
SELECT city FROM Students
UNION
SELECT city FROM Employees;
```

This query combines the cities from both tables and displays each distinct city only once.

### Important Rules

- Each `SELECT` statement must return the same number of columns.
- Corresponding columns should have compatible data types.
- `UNION` removes duplicate rows.

---

## 2. UNION ALL

### What is UNION ALL?

`UNION ALL` combines the results of multiple `SELECT` queries, including duplicate rows.

### Syntax

```sql
SELECT column_name FROM table1
UNION ALL
SELECT column_name FROM table2;
```

### Example

```sql
SELECT city FROM Students
UNION ALL
SELECT city FROM Employees;
```

If the city `Hyderabad` appears in both tables, it can appear twice in the result.

### Difference Between UNION and UNION ALL

| UNION | UNION ALL |
|---|---|
| Removes duplicate rows | Keeps duplicate rows |
| May require extra processing | Usually faster because it does not remove duplicates |
| Returns distinct combined results | Returns all combined results |

---

## 3. INTERSECT

### What is INTERSECT?

`INTERSECT` returns only the distinct rows that appear in the results of both `SELECT` queries.

### Syntax

```sql
SELECT column_name FROM table1
INTERSECT
SELECT column_name FROM table2;
```

### Example

```sql
SELECT city FROM Students
INTERSECT
SELECT city FROM Employees;
```

This query returns cities that exist in both tables.

### Important Point

`INTERSECT` is supported in MySQL 8.0.31 and later. In older MySQL versions, you can use an alternative approach such as `INNER JOIN` or `EXISTS`, depending on the requirement.

---

## 4. EXCEPT

### What is EXCEPT?

`EXCEPT` returns distinct rows from the first query that do not appear in the second query.

### Syntax

```sql
SELECT column_name FROM table1
EXCEPT
SELECT column_name FROM table2;
```

### Example

```sql
SELECT city FROM Students
EXCEPT
SELECT city FROM Employees;
```

This query returns cities found in `Students` but not in `Employees`.

### Important Point

`EXCEPT` is supported in MySQL 8.0.31 and later.

**Remember:** The order of queries matters. Reversing the two queries can produce a different result.

---

## 5. INNER JOIN

### What is INNER JOIN?

`INNER JOIN` combines rows from two tables when their specified join condition matches.

### Example Tables

**Students**

| student_id | student_name | dept_id |
|---:|---|---:|
| 1 | Ravi | 10 |
| 2 | Priya | 20 |
| 3 | Kumar | 30 |

**Departments**

| dept_id | dept_name |
|---:|---|
| 10 | Computer Science |
| 20 | Commerce |
| 40 | Mechanical |

### Syntax

```sql
SELECT columns
FROM table1
INNER JOIN table2
ON table1.column_name = table2.column_name;
```

### Example

```sql
SELECT
    Students.student_name,
    Departments.dept_name
FROM Students
INNER JOIN Departments
ON Students.dept_id = Departments.dept_id;
```

### Result

| student_name | dept_name |
|---|---|
| Ravi | Computer Science |
| Priya | Commerce |

Kumar is not included because department ID `30` does not match any department in the `Departments` table.

### Important Point

`INNER JOIN` returns only rows that satisfy the join condition.

---

## 6. EQUI JOIN

### What is EQUI JOIN?

An **Equi Join** is a join that uses the equality operator (`=`) to match related values in two tables.

It is commonly written using `INNER JOIN` with an equality condition.

### Example

```sql
SELECT
    Students.student_name,
    Departments.dept_name
FROM Students
INNER JOIN Departments
ON Students.dept_id = Departments.dept_id;
```

The condition `Students.dept_id = Departments.dept_id` makes this an equi join.

### Important Point

An equi join is based on equality. It is a type of join condition, not a separate SQL keyword.

---

## 7. NATURAL JOIN

### What is NATURAL JOIN?

`NATURAL JOIN` automatically joins two tables using columns that have the same names in both tables.

### Example

Suppose `Students` and `Departments` both contain a column named `dept_id`.

```sql
SELECT student_name, dept_name
FROM Students
NATURAL JOIN Departments;
```

MySQL automatically uses the common column name `dept_id` to match rows.

### Advantages

- Less code is required.
- You do not need to write an explicit `ON` condition.

### Disadvantages

- It may produce unexpected results if tables share additional column names.
- Changes to table structures can change the join behavior.
- It can be less clear to someone reading the query.

### Best Practice

For most real-world projects, an explicit `JOIN ... ON` condition is easier to understand and maintain.

---

## 8. NON-EQUI JOIN

### What is NON-EQUI JOIN?

A **Non-Equi Join** uses a comparison condition other than equality (`=`), such as `<`, `>`, `<=`, `>=`, or `BETWEEN`.

### Example Tables

**Employees**

| employee_name | salary |
|---|---:|
| Ravi | 30000 |
| Priya | 50000 |

**SalaryGrades**

| grade | min_salary | max_salary |
|---|---:|---:|
| A | 20000 | 39999 |
| B | 40000 | 59999 |
| C | 60000 | 80000 |

### Example

```sql
SELECT
    Employees.employee_name,
    Employees.salary,
    SalaryGrades.grade
FROM Employees
JOIN SalaryGrades
ON Employees.salary
   BETWEEN SalaryGrades.min_salary
   AND SalaryGrades.max_salary;
```

### Result

| employee_name | salary | grade |
|---|---:|---|
| Ravi | 30000 | A |
| Priya | 50000 | B |

The salary is matched to the appropriate salary range instead of matching two columns with `=`.

### Common Uses

- Matching salaries to salary grades.
- Matching products to price ranges.
- Matching dates to date ranges.

---

## 9. SELF JOIN

### What is SELF JOIN?

A **Self Join** joins a table with itself. It is useful when rows in the same table are related to one another.

For example, an employee table may store both employee details and the ID of that employee's manager.

### Example Table: Employees

| employee_id | employee_name | manager_id |
|---:|---|---:|
| 1 | Anil | NULL |
| 2 | Ravi | 1 |
| 3 | Priya | 1 |
| 4 | Kumar | 2 |

### Syntax

```sql
SELECT columns
FROM table1 AS a
JOIN table1 AS b
ON a.column_name = b.column_name;
```

### Example

```sql
SELECT
    e.employee_name AS employee,
    m.employee_name AS manager
FROM Employees AS e
LEFT JOIN Employees AS m
ON e.manager_id = m.employee_id;
```

### Result

| employee | manager |
|---|---|
| Anil | NULL |
| Ravi | Anil |
| Priya | Anil |
| Kumar | Ravi |

### Explanation

- `e` is an alias for the employee record.
- `m` is an alias for the manager record.
- `e.manager_id = m.employee_id` connects each employee to their manager.
- `LEFT JOIN` keeps employees who do not have a manager, such as Anil.

### Common Uses

- Finding employees and their managers.
- Comparing products in the same table.
- Finding related records in hierarchical data.

---

## Quick Revision

| Concept | Purpose |
|---|---|
| UNION | Combines query results and removes duplicates |
| UNION ALL | Combines query results and keeps duplicates |
| INTERSECT | Returns rows common to both query results |
| EXCEPT | Returns rows in the first result but not the second |
| INNER JOIN | Returns matching rows from two tables |
| EQUI JOIN | Joins using an equality condition (`=`) |
| NATURAL JOIN | Automatically matches columns with common names |
| NON-EQUI JOIN | Joins using range or other non-equality conditions |
| SELF JOIN | Joins a table with itself |

## Final Note

Set operators such as `UNION`, `INTERSECT`, and `EXCEPT` combine **query results vertically**. Joins combine related columns from tables **horizontally**, based on a join condition.

Practising these concepts will help you write queries for real-world databases such as student management, employee management, and sales systems.
