## 1. What is Data?

**Data** means raw facts or information that can be stored and processed by a computer.

Data by itself may not give us complete meaning. When data is organized and processed, it becomes useful information.

### Examples of Data

```text
Name: Bunny
Age: 20
Course: Python
Marks: 85
```

Here:

* `Bunny` → data
* `20` → data
* `Python` → data
* `85` → data

A collection of such values can be stored in a database.

### Real-life example

In a college, student information may include:

```text
Student ID: 101
Name: Rahul
Age: 20
Department: CSE
Marks: 85
```

All these values are examples of data.

---

# 2. What is a Field?

A **field** is a single category or attribute of data in a table.

In a database table, a field is usually represented by a **column**.

### Example

| Student_ID | Name  | Age | Department |
| ---------- | ----- | --- | ---------- |
| 101        | Rahul | 20  | CSE        |
| 102        | Priya | 21  | ECE        |

Here:

* `Student_ID` is a field
* `Name` is a field
* `Age` is a field
* `Department` is a field

So, simply:

> **Field = Column**

### Example from real life

For a student, possible fields are:

```text
Student_ID
Name
Age
Email
Phone
Department
```

Each field stores one particular type of information.

---

# 3. What is a Record?

A **record** is a complete set of related information about one particular item or person.

In a database table, a record is usually represented by a **row**.

### Example

| Student_ID | Name  | Age | Department |
| ---------- | ----- | --- | ---------- |
| 101        | Rahul | 20  | CSE        |
| 102        | Priya | 21  | ECE        |

The first row:

```text
101 | Rahul | 20 | CSE
```

is one record.

The second row:

```text
102 | Priya | 21 | ECE
```

is another record.

So:

> **Record = Row**

### Easy way to remember

```text
Field  → Column
Record → Row
```

---

# 4. What is a Database?

A **database** is an organized collection of related data that can be stored, managed, accessed, and updated easily.

Instead of keeping information in many separate files, a database allows us to organize information in a structured way.

### Example

Imagine a college database containing student information:

| Student_ID | Name  | Age | Department |
| ---------- | ----- | --- | ---------- |
| 101        | Rahul | 20  | CSE        |
| 102        | Priya | 21  | ECE        |
| 103        | Arjun | 20  | IT         |

This table stores student-related data in an organized form.

A database can contain many tables.

For example:

```text
College Database
│
├── Students
├── Courses
├── Faculty
├── Fees
└── Attendance
```

### Real-world examples of databases

Databases are used in:

* Banking systems
* E-commerce websites
* Colleges and universities
* Hospitals
* Railway and airline systems
* Social media applications
* Online shopping applications
* Company management systems

# 5. Limitations of File Management System

Before DBMS became common, organizations often stored information using a **file management system**.

For example:

```text
Students.txt
Fees.txt
Attendance.txt
Courses.txt
```

This approach works for small amounts of information, but it creates several problems when the data becomes large.

## Main limitations

### 1. Data Redundancy

The same data may be stored in multiple files.

For example, a student's name might appear in:

```text
Students.txt
Fees.txt
Attendance.txt
```

This creates duplicate data.

---

### 2. Data Inconsistency

If the same information exists in multiple places, changing it in one file but not another can create different values.

Example:

```text
Students.txt → Rahul Kumar
Fees.txt     → Rahul
```

Now the information is inconsistent.

---

### 3. Difficult Data Access

Finding specific information from many files can be difficult.

For example:

> Find all CSE students who scored more than 80 marks.

With separate files, this may require checking multiple files manually or writing additional programs.

---

### 4. Difficult Data Sharing

Different applications may need access to the same data.

Managing shared data using separate files can become complicated.

---

### 5. Security Problems

Controlling who can access or modify particular information is more difficult with a basic file system.

For example:

```text
Student → Can view own marks
Teacher → Can update marks
Admin   → Can manage student records
```

A proper DBMS provides better ways to control access.

---

### 6. Data Isolation

Data may be stored in different files and formats.

Because of this, combining information from different files can be difficult.

---

### 7. Difficult Backup and Recovery

If a file is accidentally deleted or damaged, recovering the required information can be difficult without a proper backup system.

---

# 6. Advantages of DBMS

**DBMS** stands for **Database Management System**.

It is software used to create, store, manage, retrieve, and control data in databases.

Examples:

* MySQL
* PostgreSQL
* Oracle Database
* Microsoft SQL Server
* SQLite

## Major advantages of DBMS

### 1. Reduces Data Redundancy

A DBMS can reduce unnecessary duplication of data by organizing information properly.

---

### 2. Maintains Data Consistency

When data is updated properly, the database can maintain consistent information.

---

### 3. Better Data Security

A DBMS can provide access control.

For example:

```text
Admin     → Full access
Teacher   → Marks and student information
Student   → Limited personal information
```

---

### 4. Easy Data Access

We can use SQL queries to quickly find the required information.

Example:

```sql
SELECT * FROM students;
```

This retrieves the records from the `students` table.

---

### 5. Easy Data Management

We can easily:

* Insert data
* Update data
* Delete data
* Search data
* Sort data
* Filter data

---

### 6. Backup and Recovery

DBMS systems provide mechanisms that help organizations protect data and recover it after failures.

---

### 7. Data Sharing

Multiple users or applications can work with the same database while the DBMS manages access.

---

### 8. Maintains Data Integrity

A DBMS can apply rules to make sure that incorrect or invalid data is not stored.

For example, a student ID can be required to be unique.

---

# 7. DBMS vs File System

Both file systems and DBMS can be used to store data, but they work differently.

| Feature            | File System          | DBMS                                |
| ------------------ | -------------------- | ----------------------------------- |
| Data storage       | Files                | Database                            |
| Data redundancy    | Usually higher       | Can be reduced                      |
| Data consistency   | More difficult       | Better control                      |
| Security           | Basic                | More advanced                       |
| Data searching     | More difficult       | Easy using SQL                      |
| Data sharing       | Limited              | Better support                      |
| Backup & recovery  | Usually manual/basic | Better support                      |
| Data integrity     | Limited              | Stronger control                    |
| Multiple users     | Difficult to manage  | Better support                      |
| Data relationships | Difficult            | Easy using tables and relationships |

### Simple example

Suppose a college stores student information in separate files:

```text
Students.txt
Fees.txt
Attendance.txt
Marks.txt
```

If the same student's details appear in several files, maintaining those details becomes difficult.

With a DBMS, related information can be organized into tables and connected using relationships.

# Simple Example to Remember Everything

Imagine a **College Database**.

```text
Database
   ↓
Students Table
   ↓
+------------+---------+-----+------------+
| Student_ID | Name    | Age | Department |
+------------+---------+-----+------------+
| 101        | Rahul   | 20  | CSE        |
| 102        | Priya   | 21  | ECE        |
+------------+---------+-----+------------+
```

Here:

* `Students` → Table
* `Student_ID` → Field
* `Name` → Field
* `Age` → Field
* `Department` → Field
* `101, Rahul, 20, CSE` → Record
* `102, Priya, 21, ECE` → Record
* Entire collection → Database
